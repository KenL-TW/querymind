# QueryMind P1.1 Production Quality Release

Status: implementation complete; P2 remains investigation-only.

## Scope

P1.1 preserves the frozen P0 Governed Query Safety Core and P1 Explainable Query Experience. The patch is limited to deterministic explainability quality, result rendering, and focused regression coverage. It introduces no new product capability, migration, policy model, AI prompt contract, or execution path.

## Reproduced issues and root causes

| Issue | Evidence-backed root cause | Resolution |
| --- | --- | --- |
| Explainability provenance was too generic | `queryUnderstanding` inferred facts from prompt keywords and `WHERE` presence instead of validated query structure | Metrics now come from aggregate functions; dimensions come only from bounded `GROUP BY` expressions; business filters come only from explicit prompt phrases |
| Phantom/generic dimensions | A `group by` boolean produced `grouped dimensions`; prompt words could mark status/product/customer without a grouped expression | Removed heuristic dimensions and map only recognized grouped columns |
| Business filters mixed with governance | The old “query filters applied” label treated SQL/governance mechanics as a user business filter | Explicit prompt filter labels are separated from governance caveats/chips |
| Empty SQL section | Raw SQL property was emitted whenever authorization was true, including an empty string | SQL is included only when authorized and non-empty after trimming; UI repeats this guard |
| Generic result headers | Result keys were used directly as headers; established aliases had no human label map and columns lacked visible separation | Added approved UI display labels with safe humanized fallback and vertical cell separators |
| Markdown appeared escaped/literal | Assistant messages were always rendered as escaped paragraphs | Added an escape-first, bounded Markdown renderer for paragraphs, lists, emphasis, and inline code; no raw HTML or links are trusted |
| Awkward explainability heading | The section kicker and fallback headline could visually read as “可解釋查詢查詢完成” | Heading now uses “查詢說明” with a separate result summary fallback |
| “How calculated” could imply policy details | Business explanation included authorization and masking claims alongside calculation facts | Business explanation contains deterministic source/metric/group/filter/result facts; governance remains in structured governance and caveat fields |

## Protected behavior

- All chat and direct-query execution still calls `authorizeQuery` and executes only the returned governed SQL.
- EffectiveScope is still resolved before schema/glossary context retrieval.
- P0 table, column, row-policy, DLP, read-only, rate-limit, model-egress, and production fail-closed invariants are unchanged.
- P1 successful-run explainability and owner-only idempotent feedback are unchanged.
- Raw row predicates, scope keys, secrets, credentials, and unauthorized schema remain absent from explainability and model context.

## Focused tests added

`cloudflare/tests/explainability.spec.ts` now covers:

1. dimensions derived only from actual `GROUP BY` expressions;
2. no phantom “grouped dimensions” or WHERE-only status dimension;
3. explicit business filter labels without generic filter text;
4. empty raw SQL omission;
5. governance/business separation and no scope/predicate leakage;
6. existing raw SQL capability contract and both feedback contracts remain covered.

The product E2E assertion additionally checks the humanized result header, “查詢說明” label, non-empty authorized SQL disclosure, and absence of the awkward duplicate heading.

## Production Regression Hotfix — 2026-08-24

**Status: Worker deployed; authenticated production re-smoke remains a manual
gate.** This is a bounded P1.1 regression hotfix, not a P2-C start and not a
policy, schema, migration, secret, or production-variable change.

### Root cause and fix

- The deterministic, display-only `aliasesFromSql` helper accepted an implicit
  alias after `FROM order_items` and could consume the following `JOIN` token.
  It then skipped `products`, so the already validated expression
  `GROUP BY products.name` could not be mapped to the `product` dimension.
  The first data-loss point was explainability extraction after governed SQL
  validation; neither `QueryPolicyEngine` nor D1 execution was bypassed.
- The helper now refuses SQL join/clause keywords as implicit aliases. It
  continues to be display-only; query authorization remains exclusively in
  `QueryPolicyEngine`.
- The raw-SQL contract is defensive on both sides of the response boundary:
  the Worker emits `rawSqlAvailable: false` and omits `sql` when the validated
  SQL is empty or whitespace, while the frontend trims before rendering either
  the SQL tab or the verified-SQL disclosure.
- `NameTotal Revenue` was confirmed as adjacent `<th>` text extraction, not a
  visual defect. The actual UI uses two table cells with a 1px separator and
  human-readable labels.

### Regression coverage

- Qualified no-alias join: `GROUP BY products.name` yields metric `sales
  amount` and dimension `product`.
- Multiple qualified dimensions yield `product` and `location`; aggregate-only
  SQL yields no phantom dimension.
- Owner-capable SQL is visibly non-empty; a caller temporarily stripped of
  `view_schema` can execute a governed direct query but receives neither a top
  level SQL field nor explainability SQL.
- A browser E2E fixture with `rawSqlAvailable: true` and whitespace SQL renders
  neither an SQL tab nor disclosure, and proves the separate header cells.

## Limitations carried forward

- Explainability parsing is deliberately bounded and is not a full SQL AST or semantic model. Complex expressions, aliases, calculated dimensions, and unknown aggregates may be omitted rather than guessed.
- Cloudflare D1 remains SQLite-compatible with bounded result/response budgets; the product remains read-only and does not provide cross-database joins or ETL.
- P2 semantic assets, approval workflow, relationship contracts, metric formulas, and runtime semantic planning are not implemented by this release.
