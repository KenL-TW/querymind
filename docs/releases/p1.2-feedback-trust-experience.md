# QueryMind P1.2 — Feedback & Trust Experience

## Scope

P1.2 extends the released P1 feedback contract into a structured, evidence-linked correction capture flow. It is capture-only: feedback is not Semantic Truth, approved knowledge, a prompt change, or an automatic learning action.

The existing static SPA and Worker remain the runtime architecture. P0 governed execution, P1 Explainability, P2-D design-time suggestions, and all authentication/RBAC boundaries are unchanged.

## Contract and storage

APP migration `0011_feedback_trust_experience.sql` adds `feedback_version`, `target_type`, `target_ref`, `issue_category`, and `correction_text` to `query_feedback`. The migration is forward-only and does not alter released migration `0007`, rewrite existing rows, or add a DATA migration. Historical rows retain `feedback_version = 'p1'` and default to `WHOLE_ANSWER`.

`POST /api/v1/query-runs/:queryRunId/feedback` accepts the released P1 lowercase body and the P1.2 body (`version: p1.2`, `POSITIVE` / `NEEDS_ADJUSTMENT`, bounded target/category/comment/correction). The server verifies owner + successful QueryRun and validates every evidence reference against the stored deterministic Explainability envelope. The existing unique `(query_run_id, user_id)` upsert remains the idempotency boundary.

P1.2 feedback submission performs no OpenAI/AI Gateway call, business SQL execution, QueryPolicyEngine execution, semantic mutation, suggestion mutation, or runtime semantic lookup. Audit metadata is limited to feedback/run/version/rating/target/category identifiers; free-form text and sensitive query data are excluded.

## User experience

The default answer view presents one compact row: `這份結果符合你的需求嗎？` with `✓ 符合需求` and `調整一下`. Positive feedback is one request with a whole-answer target. Adjustment progressively discloses target, bounded issue type, and an optional correction note. Metric, dimension, filter, source, intent, and calculation evidence rows use small inline `調整` actions that open the same composer. Errors keep the answer and typed correction visible and expose a retry action. Controls are keyboard/focus accessible and stack at narrow widths.

All dynamic evidence and user text are escaped in the SPA; correction/comment values are never interpreted as HTML, Markdown, SQL, JSON paths, or prompt instructions.

## Verification and deployment

Record exact local/CI/production results in the machine-readable manifest `docs/releases/manifests/p1.2-feedback-trust.json` and the final handover. The P2-D manual production suggestion smoke remains independent and `PENDING`; P2-E and P2-F are not started. If an authenticated production browser session is not supplied by the operator, authenticated UX smoke is reported as `NOT EXECUTED BY DESIGN` rather than inferred.

Future retention policy must cover feedback metadata, comment/correction text, and its audit reference. No retention engine or feedback review/learning console is introduced here.
